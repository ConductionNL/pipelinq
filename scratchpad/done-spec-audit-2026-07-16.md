## Corrections to prior triage / tooling (important — both would have caused wrong work)

1. **Team memory's ADR-022 flag on `lib/Service/Avg/*` + `Mdm/SyncQueueService` is STALE.** Neither exists at HEAD. Both were deliberately retired and **both retirement commits are ancestors of HEAD**: `023922c6d` (AVG stack → OR's `dataSubjectRequest` DSAR engine, ADR-047 Phase 3) and `0363a7c1d` (app-side sync queue → OR `WebhookService`, ADR-045). Both cutovers are **live-wired**, not phantom: `lib/AppInfo/Application.php:681,734-738` (EvidenceSourceRegistry), `:220-224` (ObjectsMergedEvent listener), `appinfo/info.xml:133-135` (repair steps). The surviving `SyncQueueService` strings are docblocks *describing the retirement*. **Nothing to fix here.**
2. **`check_register_handler_resolution.py` emits 7 FALSE POSITIVES on pipelinq** — `guard-class-not-found` for `PosTransactionConfirmGuard`, `PosTransactionAccessGuard` (×3), `PosTransactionRefundGuard`, `PosRefundManagerGuard` (×2) on posTransaction/posRefund money transitions. **All four classes exist** (`lib/Lifecycle/`) and are **live-registered** at `lib/AppInfo/Application.php:436,443,455,462`. The script fails to resolve `requires` targets. This is a **hydra tooling bug, not an app defect** — and a dangerous one, since it cries wolf on the money path. Worth a hydra issue.

## Coverage

- **Exhaustive:** all 10 orphan-scan findings under `lib/Service/**` triaged with an explicit superseded-check each; handler-resolution gate (all 7 findings run to ground); the flagged ADR-022 targets (Avg/Mdm) verified against HEAD *and* git history; the portal auth/MFA session path; `@spec` anchor existence for the flagged files.
- **Sampled:** the 66 `done` specs were **not** each independently verified. I drove from defect shapes into specs, not spec-by-spec. Specs with no orphan-scan signal — the large declarative/UI surface (`dashboard`, `navigation-ia`, `declarative-view-system`, `my-work`, `kennisbank`, marketing-*, pos-* UI) — are **unverified here**; they need a browser pass.
- **UNSURE:** the DEAD verdicts scope "callers" to `lib/`, `appinfo/`, `src/`, `tests/` and this app's `Application.php`. If any method is reached via an OR-side cross-app seam or container resolution outside this repo, that verdict would need rechecking. No such seam appears in this app's registrations.

## Bottom line

Of **66 `done`** specs, the audit **confirms at least 5 that do not run**: `email-calendar-sync` (whole class dead), `notifications-activity` (orphan + stub cron job), and three requirements inside `appointment-booking` — REQ-APT-010 deposits, REQ-APT-012 walk-in queue, REQ-APT-018 calendar sync. `master-data-management` is **partial** (live, with dead residue its spec still advertises). Two money-path features — **deposits and gift cards** — are provably unreachable, and the **entire ZGW write bridge** (zaak/document/besluit) is dead while the register.d description still claims it is in use. Two prior beliefs were **wrong and are corrected above** (Avg/Mdm already retired; 7 POS guard "failures" are a tooling false positive). The remaining ~60 `done` specs showed no defect signal but were **not exhaustively verified** — the shillinq base rate suggests the declarative/UI surface deserves its own pass.
