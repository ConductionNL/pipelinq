# Design: Pipelinq views → declarative (round 1)

## Audit classification (A = convertible, C = not yet)

### Step 1 — dead orphan views (deleted)

Nine of the ten audit-listed orphan views were already removed in the prior
`werkplek-superseded` cleanup commit (`dee851b2`) and confirmed gone with zero
importers: `clients/ClientList.vue`, `complaints/ComplaintCreateDialog.vue`,
`products/ProductCreateDialog.vue`, `AdminSettingsExportPage.vue`,
`UserSettings.vue`, and the four bespoke detail orphans
`leads/LeadDetail.vue`, `complaints/ComplaintDetail.vue`,
`products/ProductDetail.vue`, `requests/RequestDetail.vue`. The four detail
pages are already declarative `type:"detail"` manifest pages (`LeadDetail`,
`ComplaintDetail`, `ProductDetail`, `RequestDetail` with sidebar tabs) — the
behaviour is covered, the `.vue` files were unreferenced.

`avg/AvgIntakeView.vue` was listed as a "thin wrapper" orphan but is **NOT
dead** — it is imported, registered, reachable via the manifest page `AvgIntake`
(`/avg-verzoeken/nieuw`) and navigated to from `AvgDashboard.vue`. It hosts a
bespoke 142-line `AvgIntakeForm` (multi-field intake + create + post-create
navigation). **KEPT** — deleting it would break the AVG intake flow.

| Page | Class | Decision | Reason |
|------|-------|----------|--------|
| Analytics | C | KEPT custom | the four KPIs come from a single server-side cross-module summary endpoint `GET /api/analytics/summary?period=` (REQ-KB360-020) that pre-aggregates across leads/requests/contactmomenten so large installs never fetch full collections client-side; the declarative dashboard stat-widget `dataSource` only reads a per-schema OR aggregate, not an arbitrary REST endpoint. ## Declarative column renderers used (nc-vue)

- Status badge with per-value colour: `{ "key": "status", "widget": "badge",
  "widgetProps": { "colorMap": { "<value>": "<variant>" } } }` (variants:
  `default | primary | success | warning | error | info`).
- Date / datetime: `{ "key": "...", "format": "date" | "date-time" }`.
- Boolean checkmark: `{ "key": "...", "type": "boolean" }`.
- Row navigation: `actions: [{ id, label, icon, handler:"navigate", route }]` →
  `$router.push({ name: route, params: { id: row[rowKey] } })`. `route` is the
  target manifest page id (which is also the vue-router route name).
- All mass actions and the schema form dialog are turned off
  (`showAdd/showFormDialog/showView…/showMass…: false`) on the converted pages,
  because they deliberately route to bespoke detail/editor views rather than
  the built-in CnFormDialog.

## Missing nc-vue primitives surfaced by this round (round-2 backlog)

1. **Declarative currency cell renderer** — unblocks Services, Projects.
2. **Declarative colour-swatch cell renderer** — unblocks BillingCategories.
3. **Declarative / static-param header action** (e.g. a header create action
   that navigates to a detail route with a literal `id:'new'`) — unblocks the
   create-to-detail entry point on Resources, Services, Projects.
4. **Declarative custom multi-key sort** — unblocks BillingCategories' sort.
5. **Stat widget with a custom-REST-endpoint dataSource + a page-level filter
   primitive that propagates a param to widget dataSources** — unblocks
   Analytics.
